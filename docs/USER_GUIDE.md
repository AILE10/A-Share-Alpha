# A-Share Alpha Studio 完整使用说明手册（保姆级实战版）

> **系统定位**：面向个人投资者的 **A 股全栈实时量化投研、Walk-Forward 样本外回测优化、实时模拟实盘与合规半自动/QMT 辅助交易系统**。
>
> **五大底线保障**：① 100% 真实 A 股行情与公告日财报（严禁 Mock 随机数）；② 严格 A 股 T+1、百股、涨跌停封板与真实税费滑点；③ 财务公告日 PIT 对齐 + 至少 5 日 Embargo 隔离防未来函数；④ 统一前置风控中间件拦截与审计；⑤ 严格合规（无逆向抓包/外挂模拟点击）。
>
> **风险提示**：本系统用于量化投研、模拟验证与辅助决策，不构成任何投资收益承诺。股市有风险，实盘交易请结合自身风险承受能力独立决策。

## 一、环境要求与安装启动

### 1.1 运行环境要求
- **操作系统**：Windows 10/11（主力推荐）、macOS 或 Linux
- **Python**：3.11 或以上（本机已验证 3.12.9）
- **Node.js**：18 或以上（含 npm）
- **硬盘空间**：同步 250~500 只股约需 200~400 MB；同步全市场 3,000+ 只活跃股约需 1~2 GB

### 1.2 三种一键启动方式

| 启动方式 | 执行命令 | 适用场景 |
| :--- | :--- | :--- |
| **Windows 一键脚本（推荐）** | `powershell -ExecutionPolicy Bypass -File scripts\start_dev.ps1` | Windows 日常一键同时拉起前后端 |
| **macOS / Linux 一键脚本** | `chmod +x scripts/start_dev.sh && ./scripts/start_dev.sh` | Mac/Linux 本地开发运行 |
| **Docker 容器化一键部署** | `docker compose up -d --build` | 长期后台挂机 / 迁移到云服务器或 NAS |

**手动分窗口启动**（方便分别观察日志）：
- 终端 1（后端 API + 定时任务）：
  ```powershell
  cd backend
  .venv\Scripts\uvicorn.exe app.main:app --host 127.0.0.1 --port 8000
  ```
- 终端 2（前端可视化界面）：
  ```powershell
  cd frontend
  npm run dev
  ```

### 1.3 访问入口与启动成功检查
- **量化工作台主界面**：`http://localhost:5173`
- **后端 Swagger 接口文档**：`http://127.0.0.1:8000/docs`
- **健康检查接口**：`http://127.0.0.1:8000/api/v1/health`

打开 `http://localhost:5173` 后，确认页面**最顶部状态栏**正常亮起：
1. **大盘状态灯**：`强势进攻 (90%)` / `震荡中性 (55%)` / `弱势防守 (10%~15%)`；
2. **执行模式徽章**：`高精度模拟盘` / `半自动辅助` / `合规QMT桥接`；
3. **风控水位**：`风控正常` / `回撤预警` / `回撤熔断`；
4. **右上角绿灯**：`实时推流在线`（表示 WebSocket 实时通道已连通）。

## 二、数据同步指南（免 Token 方案 A）

本系统采用 **DuckDB（分析行情库）+ SQLite（交易状态库）** 本地持久化架构，所有策略、因子、回测与选股都会**自动分析本地 DuckDB 中已同步的全部股票**。

> **重要提醒**：DuckDB 单文件同一时刻只允许一个进程写入。在命令行运行大规模同步脚本前，请先**暂时关闭正在运行的后端 `uvicorn` 窗口**（或者直接不关后端、点前端右上角的「全市场活跃股同步」按钮由后端线程统一写库）。

### 2.1 四种常用数据同步命令（支持随时中断、重跑自动断点续传）

```powershell
# ① 快速扩容：同步全市场成交额前 300 只活跃 A 股（近 2 年）+ 重算因子 + 重训模型（约 2~3 分钟）
backend\.venv\Scripts\python.exe -u scripts\sync_full_market.py --max-stocks 300 --retrain

# ② 进阶扩容：同步全市场成交额前 1000 只活跃 A 股（近 2 年）+ 重训模型（约 10 分钟）
backend\.venv\Scripts\python.exe -u scripts\sync_full_market.py --max-stocks 1000 --retrain

# ③ 全市场活跃股全覆盖：不设上限，自动同步全市场成交额 ≥ 4000 万的全部约 3,000 只活跃 A 股（约 25~35 分钟，可随时 Ctrl+C 中断，重跑自动跳过已完成的股票）
backend\.venv\Scripts\python.exe -u scripts\sync_full_market.py --retrain

# ④ 5 年跨牛熊深度回测专用：把历史拉长到 5 年（1825 天，加 --no-resume 强制向前补齐历史）
backend\.venv\Scripts\python.exe -u scripts\sync_full_market.py --max-stocks 300 --days 1825 --no-resume --retrain
```

### 2.2 常用命令行参数一览
- `--max-stocks N`：限制拉取活跃股数量；不传则拉取全部活跃 A 股（约 3,000 只）
- `--min-amount 40000000`：预筛成交额门槛（默认 4,000 万元，略宽于策略 5,000 万元动态门槛以防漏选）
- `--days 730`：历史天数（日常实盘建议 `730` = 2 年；跨牛熊压力测试建议 `1825` = 5 年）
- `--workers 4`：并发线程数（默认 4，网络稳可设 5~6，不建议超过 6 以防限流）
- `--all-market`：跳过 4,000 万成交额预筛，拉取全部近 5,000 只非 ST 成熟 A 股
- `--no-resume`：不跳过已有缓存，强制重新拉取更新全段历史
- `--force-refresh-fin`：强制重新拉取最新季度全市场 PIT 公告日财报（财报季结束后可运行一次）
- `--retrain`：同步完自动重训 LightGBM 模型快照并生成最新推荐信号

## 三、内置默认核心策略通俗解读

系统默认内置并完整跑通的复合策略为 **「中小盘多因子增强 + LightGBM 截面排序 + 技术面共振与大盘状态择时」**，每 5 个交易日调仓一次，核心分 5 层漏斗：

1. **第一层 · 动态排雷过滤（Universe Filter）**：
   每天自动踢掉 ST/*ST 退市风险股、停牌股、上市不足 120 交易日的次新股、近 20 日日均成交额低于 5,000 万元的“僵尸股”、总市值全市场后 10% 的极端微盘股。
2. **第二层 · 四维 16 因子横截面打分**：
   从**量价动量反转**（20/60日收益、5日反转、量价相关性、日内收盘位置）、**流动性与资金流**（20/60日异常换手、Amihud非流动性、5日量比、主力净流入）、**波动率与筹码**（特质波动率、下行波动率占比、60日价格分位）、**基本面质量**（EP、BP、ROE_TTM、单季净利同比，严格按财报真实公告日对齐）四个维度刻画每只股票，经去极值、申万一级行业与市值中性化后标准化。
3. **第三层 · LightGBM 截面排序（严格防过拟合）**：
   采用 **Purged Walk-Forward 滚动训练**（默认过去 252 个交易日训练 → 清洗跨界标签并隔离至少 5 个交易日 Embargo → 预测未来 63 个交易日），输出每只股票的综合得分及 **TreeSHAP 单股贡献拆解**，取前 30 名进入候选池。
4. **第四层 · 技术面共振 + 换手缓冲带 + 风险平价优化**：
   - **技术共振**：要求收盘价站上 20 日均线（或均线多头 / 缩量回踩 MA20 企稳），同时剔除近 3 日暴涨超 20% 的追高过热股与出现 MACD 顶背离的标的；
   - **换手缓冲带（Buffer Zone）**：手里已经持有的股票只要还排在模型前 25 且没触发止损，就不急着换掉，大幅省下印花税和滑点；
   - **风险平价（Risk Parity）**：用近 60 日收缩协方差矩阵分配 8~12 只持股权重（波动低的配重高、波动大的配重低），硬约束单票 ≤ 12%、单申万行业 ≤ 25%。
5. **第五层 · 大盘 Regime 择时 + 双重止损熔断**：
   - **三档仓位**：看中证 1000 相对 20/60 日均线 + 全市场站上 20 日均线股票占比 → 强势进攻 `90%` / 震荡中性 `55%` / 弱势防守 `10%~15%`；
   - **个股止损**：跌破成本价 `-8%` 或跌破入场后最高价回撤 `2.5 × ATR(14)` 即触发卖出；
   - **组合熔断**：账户回撤达 `-8%` 自动减半仓预警，达 `-12%` 触发熔断禁买。

## 四、6 大工作台页面逐页详细操作

### 页面 1：策略总览与大盘状态仪表盘（`/`）
- **适合什么时候看**：每天开盘前（09:25）、午盘、尾盘（14:35）必看。
- **核心区域解读**：
  - **4 张核心 KPI 卡片**：总资产与累计收益率、持仓市值与现金分布、今日大盘 Regime 信号灯与中证 1000 宽度、组合回撤与熔断状态；
  - **净值 vs 基准折线图**：红线为策略净值（模拟盘满 2 日后自动显示模拟实盘净值，初期展示最新样本外参考曲线），蓝线为中证 1000、灰虚线为沪深 300；
  - **中证 1000 与市场宽度双轴图**：直观看近 60 日大盘趋势与全市场站上 MA20 股票比例；
  - **持仓明细表**：红涨绿跌实时盈亏，蓝色数字为今日 **T+1 可卖股数**，绿色数字为每只股的**硬止损位**；
  - **风控水位条**：单票最高仓位（对标 12%）、单行业最高集中度（对标 25%）、回撤熔断消耗（对标 12%）。
- **按钮功能**：
  - `全市场活跃股同步`：在后端异步扫描全市场并断点续传拉取所有活跃股（页面顶部实时弹出蓝色进度条）；
  - `盘中快照盯市刷新`：立刻拉取当前持仓 + Top 100 实时报价，刷新盈亏与盘中止损报警；
  - `重新加载`：重新拉取最新后端数据。

### 页面 2：因子实验室（`/factors`）
- **适合什么时候看**：每周复盘或新增股票数据后，检查哪些因子依然赚钱、哪些失效。
- **核心指标通俗解释**：
  - `RankIC均值`：因子排序和未来 5 天超额收益的相关系数。绝对值 `> 0.02` 有效，`> 0.04` 极强（负值说明因子越小越好，如特质波动率越低越容易涨）；
  - `RankICIR`：IC 均值 ÷ IC 波动率，越高说明这个因子“赚得稳、不抽风”；
  - `IC胜率`：有多少期因子方向是对的（>55% 或 <45% 都代表方向鲜明）；
  - `衰退监控`：`稳定有效`（绿/青）/ `近20日衰减`（黄，近期力度腰斩）/ `IC反转预警`（红，近 20 日方向反了）；
  - `降级` 标签：若东财资金流历史接口临时限流，系统标出 `降级` 并以 0 中性处理，绝不伪造随机数。
- **交互操作**：
  - **点击左侧表格任意一行因子** → 右侧联动更新该因子的 **5 分层净值曲线（Q1~Q5 与多空 LS）**（理想因子 5 条线应整齐分层、Q5 与 Q1 越拉越开）与 **累计 IC / 20 日滚动 IC**；
  - 底部查看 **16×16 相关性热力图**（深红/深绿格子代表两个因子高度相关）；
  - 点击右上角 `重算全量四维因子` 在同步新数据后刷新全部检验指标。

### 页面 3：回测与样本外优化中心（`/backtest`）
- **适合什么时候看**：调整策略参数、对比「风险平价 vs 等权」或「LambdaRank vs 回归」效果时使用。
- **操作步骤**：
  1. 在左侧参数面板设定：LightGBM 模式、组合权重方式、调仓周期（默认 5 日）、目标持股数（8~12）、换手缓冲带（默认 25）、滑点（默认 10 bps = 0.1%）、硬止损与 ATR 倍数、大盘择时与技术共振开关；
  2. 点击 **「运行 Walk-Forward 精确回测」**（等待 20~60 秒，右上角下拉框会永久保存历次运行记录供对比）；
  3. 重点评估 5 项指标：
     - **年化收益 & 相对中证 1000 超额**：是否跑赢基准；
     - **夏普比率**（>1.0 良好，>1.5 优秀）与 **卡玛比率**（年化收益 ÷ 最大回撤，>1.5 优秀）；
     - **最大回撤与修复期**：历史上最惨亏过多少、多少个交易日爬出坑；
     - **参数敏感性热力图**：看最优格子周围一片是否都偏红（稳健），还是只有单个孤立高点（警惕过拟合）；
     - **TreeSHAP & Gain 特征重要性**：检查模型是否均衡利用多维因子。

### 页面 4：实时选股推荐与 K 线透视（`/signals`）
- **适合什么时候看**：每个调仓日 14:40 前后，逐只审阅系统给出的买卖清单。
- **三栏联动操作**：
  1. **左栏（买卖/持有清单）**：点击任意标的（如 `#1 建议买入` 或 `建议调出`）；
  2. **中栏（TradingView K 线与 MACD）**：
     - 核对 K 线是否站稳蓝色 **MA20（核心共振线）**；
     - 查看图上的**绿色虚线（参考止损价）**与**红色虚线（参考止盈价）**及历史成交箭头；
     - 看下方 MACD 柱与 DIF/DEA 确认无明显顶背离；
  3. **右栏（结构化推荐归因卡片）**：
     - 看 **模型综合排名**、**建议目标仓位**、**止损/止盈参考价**；
     - 看 **Top 3 贡献因子（TreeSHAP）**：一目了然知道是“低波动+低估值”还是“业绩高增+缩量企稳”把这只票顶上了前排；
     - 看 **触发技术共振形态徽章** 和中文摘要理由；
     - 确认无误后，可直接点底部 **「经前置风控提交委托」** 下单。
- **按钮功能**：点击右上角 `实时快照重算推荐清单` 立即按最新 L1 报价刷新打分并广播至 WebSocket。

### 页面 5：模拟实盘与复盘迭代（`/paper`）
- **顶部按钮**：
  - `盘中盯市刷新`：用 Top 100 实时报价更新持仓盈亏与止损状态；
  - `立即触发 14:40 调仓`：立刻执行选股 → 风控校验 → 下单（按当前券商模式执行模拟撮合或推送半自动单）；
  - `生成周度复盘`：立即核算实盘与理论回测的偏差归因。
- **3 个标签页**：
  1. **持仓与订单流水**：核对每一笔成交股数、成交价、真实佣金/印花税/过户费/滑点，以及被 T+1、涨跌停或风控拦截的原因；
  2. **周度复盘与偏差归因**：看「模拟实盘收益 vs 理论回测收益」之间的**跟踪误差、滑点损耗、涨跌停漏单影响**，以及底部列出的**近 20 日 IC 衰减/反转因子清单**和系统给出的 `RETRAIN` / `DOWNWEIGHT` 建议；
  3. **模型版本快照与回滚**：查看历次训练的模型档案；选择 `LambdaRank` 或 `Huber 回归` 点击 **「一键滚动重训」** 生成新版本，若新版本表现不如旧版，随时点 **「一键回滚激活」** 秒级切回！

### 页面 6：券商网关与风控设置（`/broker-risk`）
- **模块 1 · 券商执行模式切换**：
  - `PAPER 模拟盘`：纯本地高精度撮合，新手首选；
  - `ASSISTED 半自动辅助`：系统发出信号后，**自动推送企业微信/钉钉 Markdown 交易单并弹出前端确认框**；你在券商 App 人工下单后，在下方 **「半自动辅助待确认队列」** 点 **「录入实盘成交」** 填入真实成交价和股数，系统自动回写持仓和盈亏，实现实盘账本同步；
  - `QMT 合规桥接`：面向已向券商官方开通迅投 MiniQMT / PTrade 程序化权限的账户（默认开启 `Dry-Run 安全演练模式`，详见 [docs/COMPLIANT_QMT_GUIDE.md](./COMPLIANT_QMT_GUIDE.md)）。
- **模块 2 · Webhook 通知配置**：粘贴企业微信或钉钉群机器人 Webhook 地址后，点击 **「测试 Webhook 推送」** 立即发一条测试消息验证连通性。
- **模块 3 · 前置风控红线设置（RiskMiddleware）**：自定义单票上限（默认 `0.12`）、申万一级行业上限（默认 `0.25`）、硬止损（`0.08`）、ATR 倍数（`2.5`）、回撤预警线（`0.08`）与熔断线（`0.12`）、每分钟/每日报撤频率上限。
- **模块 4 · 实时验证委托 & 风控审计日志**：可随时填一只股票和超大股数（如 `50000` 股）点「测试提交」，立即在下方 **前置风控拦截与放行审计日志** 看到 `SINGLE_STOCK_CAP / REJECT` 实时拦截记录。

## 五、从新手到实战：三阶段推荐路线

1. **第 1 周（熟悉与扩容验证期 · `PAPER` 模式）**：
   - 运行 `sync_full_market.py --max-stocks 1000 --retrain`（或直接全市场 3,000 只活跃股）；
   - 在第 3 页「回测中心」分别跑一次风险平价 vs 等权回测，观察最大回撤和参数热力图；
   - 保持 `PAPER` 模拟盘运行，熟悉 14:40 自动调仓与 K 线归因卡片。
2. **第 2~4 周（连续模拟实盘与复盘期 · `PAPER` 模式）**：
   - 连续跑 2~4 周真实行情模拟盘，每周五查看第 5 页「周度复盘」，盯紧**实盘-回测跟踪误差**与**滑点损耗**；
   - 体验至少一次「一键滚动重训」和「一键回滚」，确认熟悉模型迭代流程。
3. **第 5 周起（合规半自动跟单期 · `ASSISTED` 模式）**：
   - 在第 6 页配置企业微信/钉钉 Webhook，将模式切到 `ASSISTED 半自动辅助`；
   - 每个调仓日 14:40 收到推送单后，结合 K 线与止损位在券商官方 App 人工核对下单，并点「录入实盘成交」回写；
   - 如已向券商开通官方 MiniQMT 权限，可先开启 `Dry-Run=True` 演练 1 周确认无误后再考虑接入。

## 六、交易日自动化定时任务节奏

后端启动后，内置 `APScheduler` 按北京时间（`Asia/Shanghai`）自动执行 5 个任务：

| 触发时间 | 任务名称 | 自动执行的动作 |
| :--- | :--- | :--- |
| **工作日 09:26** | `pre_market_unlock` | 自动解锁前日买入持仓的 T+1 可卖股数 |
| **交易时段每 120 秒** | `intraday_top100_refresh` | 仅对当前持仓 + Top 100 候选拉取实时 L1 报价，更新浮盈亏并监控 `-8% / 2.5×ATR` 止损 |
| **工作日 14:40** | `rebalance_1440` | 全库模型打分 → Top 100 实时报价校准 → 技术共振与组合优化 → 经风控中间件执行模拟撮合或推送半自动单 |
| **工作日 15:30** | `post_market_sync` | 盘后增量日线落库 DuckDB 并记录当日净值对账基准 |
| **每周五 16:30** | `weekly_review` | 生成周度复盘报告、跟踪误差归因与近 20 日因子 IC 衰减预警 |

## 七、进阶配置指南

复制 `backend/.env.example` 为 `backend/.env` 后按需修改（重启后端生效）：
- `PAPER_INITIAL_CASH=1000000.0`：初始模拟本金（默认 100 万元，新建账户生效）
- `INTRADAY_REFRESH_SECONDS=120`：盘中快照刷新间隔（秒，建议 ≥ 60 秒）
- `SCHEDULER_ENABLED=true`：设为 `false` 可暂停后台定时任务（仅手动操作）
- `WECOM_WEBHOOK_URL` / `DINGTALK_WEBHOOK_URL` / `DINGTALK_SECRET`：机器人通知地址（也可在页面第 6 页直接配置）
- `TUSHARE_TOKEN=`：可选，如拥有 Tushare Pro Token 可填入并执行 `backend\.venv\Scripts\pip install -e "backend[tushare]"`

## 八、一键迁移到其他 Antigravity

本项目已按 Antigravity 官方插件规范打包在 `dist/` 目录（随时可运行 `backend\.venv\Scripts\python.exe scripts\package_for_antigravity.py` 重新生成，加 `--include-data` 可连同本地行情库一起离线打包）：

1. **整套系统迁移**：拷贝 `dist/a-share-alpha-studio-portable-full.zip` 到新电脑解压，用 Antigravity 打开解压后的文件夹，发一句话即可自动安装运行：
   > `请读取本项目自带的 alpha-studio-ops 技能，完成环境初始化、依赖安装、拉取真实 A 股数据、运行 pytest 验收并启动工作台。`

## 九、常见问题排查（FAQ）

1. **运行 `start_dev.ps1` 提示“无法加载文件，因为在此系统上禁止运行脚本”？**
   > 请使用带绕过参数的命令启动：`powershell -ExecutionPolicy Bypass -File scripts\start_dev.ps1`。
2. **运行命令行同步脚本报错 `DuckDB IOException: 另一个程序正在使用此文件`？**
   > DuckDB 不支持多进程同时写入。先关掉正在运行的 `uvicorn` 后端窗口再跑命令行脚本；或者不关后端，直接在网页第 1 页点「全市场活跃股同步」按钮。
3. **看到「主力资金流降级 (`DEGRADED_MISSING` / `PARTIAL_DEGRADED`)」正常吗？**
   > 正常！东方财富 `push2` 资金流接口偶尔会对公网 IP 临时限流。系统严禁造假数据，会自动把该因子标记为降级并以中性值安全参与运算，其余 15 个因子与模型不受任何影响。
4. **为什么全市场下跌时系统只建议 10%~15% 仓位？**
   > 这是大盘 Regime 择时保护生效。中证 1000 处于 20/60 日均线下方且宽度不足 35% 时自动收缩仓位保护本金；大盘转强时会自动恢复 55% 或 90%。
5. **如何清空模拟盘账本重新从 100 万开始？**
   > 停止后端服务，删除 `data/studio_state.db`（**不要删** `data/market_analytics.duckdb`，那是珍贵的历史行情库），重新启动后端即自动生成全新 100 万账户。
6. **如何验证系统所有交易规则与风控没有被改坏？**
   > 在终端运行 `cd backend && .venv\Scripts\python.exe -m pytest`，确认全部 **48 项测试** 全部通过即可。
