# A-Share Alpha Studio 全局开发与风控红线

1. **严禁 Mock 数据**：数据拉取、因子计算、回测引擎与模拟盘模块禁止使用随机数或硬编码假数据冒充真实行情，必须接入真实 A 股接口（AKShare 主 / Baostock 备，并预留 Tushare Pro 适配器）且落盘本地 DuckDB / SQLite 缓存。数据源限流或缺失（如主力资金流）时必须打标降级（`DEGRADED_MISSING` / `PARTIAL_DEGRADED`）并平滑处理，绝不捏造数据。
2. **严守 A 股交易约束**：所有回测与模拟撮合必须强制执行 T+1（当日买入不可当日卖出）、100 股整数倍买入、主板 10% / ST 5% / 创业板科创板 20% / 北交所 30% 涨跌停板限制（涨停封板无法买入、跌停封板无法卖出并顺延）、前/后复权正确对齐（因子与均线用后复权，撮合与涨跌停用未复权并处理除权除息连续性）、真实费用（佣金万 1.5 最低 5 元、卖出印花税 0.05%、过户费 0.001%、滑点）。
3. **严防未来函数与数据泄露**：财务因子必须严格按财报真实公告日（`ann_date < trade_date`）向后填充，禁止使用报告期（`end_date`）对齐；机器学习训练必须采用 Purged Walk-Forward 滚动切分，训练集与测试集之间强制保留至少 5 个交易日隔离期（Embargo）并清洗跨界标签。
4. **合规与风控底线**：券商接口采用统一抽象 `BaseBrokerAdapter` 模式（Paper / Assisted / Compliant QMT），严禁编写任何逆向抓包、内存注入或模拟点击外挂代码；任何交易信号进入执行层前必须经过统一前置风控中间件 `RiskMiddleware`（单票上限 12%、单申万一级行业上限 25%、组合回撤熔断、报撤单频率限流）并写入审计日志。
5. **真实运行验证**：任何重要功能修改或部署完成后，必须通过终端运行 `pytest` 与真实小样本 A 股脚本验证输出；涉及前端改动时必须通过 `npm run build` 并在浏览器检查页面渲染与控制台零报错。
